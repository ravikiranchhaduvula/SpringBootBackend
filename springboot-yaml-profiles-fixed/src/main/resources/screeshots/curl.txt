JDBC CRUD Endpoints

1️⃣ Create (POST)

curl -X POST "http://localhost:8081/api/users/jdbc" ^
  -H "Content-Type: application/json" ^
  -d "{\"id\":1001, \"name\":\"Ravi\", \"email\":\"ravi@email.com\"}"
2️⃣ Read All (GET)

curl -X GET "http://localhost:8081/api/users/jdbc"

3️⃣ Read One by ID (GET)

curl -X GET "http://localhost:8081/api/users/jdbc/1001"

4️⃣ Update (PUT)

curl -X PUT "http://localhost:8081/api/users/jdbc/1001" ^
  -H "Content-Type: application/json" ^
  -d "{\"name\":\"Updated Ravi\", \"email\":\"updated@email.com\"}"

5️⃣ Delete (DELETE)

curl -X DELETE "http://localhost:8081/api/users/jdbc/1001"

6) Windows CMD tests
A) Bulkhead (sync) + Retry/CB
:: success
curl -i "http://localhost:8081/api/http-demo/rc/1"

:: transient failure (503) → retried up to 3 times; if still failing, fallback
curl -i "http://localhost:8081/api/http-demo/rc/1?fail=true"

B) TimeLimiter (fail if slow > 1s)
:: 1500ms delays should trip the 1s timelimiter and hit fallback
curl -i "http://localhost:8081/api/http-demo/rc-async/2?delayMs=1500"

C) Feign + ErrorDecoder (retry 429/503/504)
:: Feign path success
curl -i "http://localhost:8081/api/http-demo/feign/3"

:: Force 503 (will retry via Retryer + ErrorDecoder; if still failing, your wrapper's CB fallback kicks in)
curl -i "http://localhost:8081/api/http-demo/feign/3?fail=true"

===============================Rate Limit ========================================================
A) Normal calls (under the limit)
curl -i "http://localhost:8081/api/http-demo/feign/1"

B) Hit the rate limit (burst more than 5 calls in 1s)
for /l %i in (1,1,10) do curl -s "http://localhost:8081/api/http-demo/feign/2" && echo.


First ~5 should be real responses.

Remaining should trigger rateLimitedFallback (you’ll see rate-limited user).

C) Combine with upstream failures
:: Will be rate-limited first; if permit OK, server returns 503 -> Retry/CB fallback
